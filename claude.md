## Data Models — Quick Reference

### CustomUser (`accounts/models.py`)
- Extends `AbstractUser`
- Extra field: `role` with choices `voter | admin | soc_analyst`
- Setting: `AUTH_USER_MODEL = 'accounts.CustomUser'` in `settings.py`

### Election, Candidate, Vote (`voting/models.py`)
- `Vote` has `unique_together = (voter, election)` — one vote per user per election
- `Candidate.vote_count` incremented atomically on each cast vote

### SecurityEvent (`ids_engine/models.py`) — Most Important Model
Every HTTP request through `LoggingMiddleware` creates one record.

| Field Group | Fields |
|---|---|
| Request metadata | timestamp, event_type, user FK nullable, ip_address, user_agent, session_id, endpoint, method, status_code, request_payload |
| Rule output | rule_triggered bool, rule_name, rule_score 0–100 |
| ML output | ml_anomaly_score float |
| Fused output | risk_score 0–100, risk_level LOW/MEDIUM/HIGH/CRITICAL, action_taken ALLOW/ALERT/BLOCK |
| Compliance | iso_control, nist_category |

## IDS Pipeline — How It Works

```
Request → LoggingMiddleware
              ↓
         run_ids_pipeline()
         /         \
  rule_engine    ml_detector
         \         /
          risk_scorer
              ↓
       decision_engine
              ↓
     compliance_mapper
              ↓
      SecurityEvent.save()
              ↓
    ALLOW / ALERT / BLOCK (403)
```

### Rule Engine — 6 Rules

| Rule | Trigger | Score | Severity |
|---|---|---|---|
| brute_force_rule | >5 LOGIN_FAIL from same IP in 60s | 80 | HIGH |
| duplicate_vote_rule | Same user + election already has Vote | 100 | CRITICAL |
| blocked_ip_rule | IP in BlockedIP model | 95 | CRITICAL |
| sql_injection_rule | Regex: OR 1=1, UNION SELECT, DROP TABLE etc | 75 | HIGH |
| rapid_request_rule | >30 requests/min from same IP | 50 | MEDIUM |
| admin_abuse_rule | Admin accessed >20 voter records in session | 70 | HIGH |

### Risk Scorer Formula
```python
final_score = (0.6 * rule_score) + (0.4 * ml_score)

if final_score > 85:   risk_level = 'CRITICAL'
elif final_score > 60: risk_level = 'HIGH'
elif final_score > 30: risk_level = 'MEDIUM'
else:                  risk_level = 'LOW'
```

### Decision Engine
| Risk Level | Action | HTTP Behaviour |
|---|---|---|
| LOW | ALLOW | Request proceeds normally |
| MEDIUM | ALERT | Request proceeds, event flagged |
| HIGH | ALERT | Request proceeds, SOC alerted |
| CRITICAL | BLOCK | Middleware returns 403 — view never runs |

### ML Score Normalisation
```python
def normalise_score(raw: float) -> float:
    clipped = max(-0.8, min(0.5, raw))
    return round((0.5 - clipped) / 1.3 * 100, 1)
# +0.5 (very normal)   → score 0
# -0.8 (strong anomaly) → score 100
```

## Common Mistakes — Read Before Every Phase

| Mistake | Consequence | Prevention |
|---|---|---|
| `AUTH_USER_MODEL` set after first migration | Must delete DB and start over | Set it BEFORE ever running migrate |
| `LoggingMiddleware` before `AuthenticationMiddleware` | `request.user` always AnonymousUser | Check middleware order every session |
| Not filtering static paths in middleware | Thousands of noise records in minutes | SKIP_PATHS check at top of middleware |
| Wrong FEATURES order | Silent wrong ML scores | Import from ml_detector.py, never redefine |
| Saving model but not scaler | Crash at inference | Always `joblib.dump()` both |
| Forgetting `chart.update()` | Charts freeze after first load | Call it at end of every `fetchAlerts()` |
| Running commands outside venv | Wrong packages, import errors | Check `(venv)` in terminal prompt always |
| Committing `.env` | SECRET_KEY exposed | `.env` must be in `.gitignore` from day one |
